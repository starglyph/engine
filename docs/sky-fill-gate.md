# Регрессионная проверка экспериментального sky-fill

`make eval-smartphone-sky-fill-gate` из `prototype/` проверяет все 17 смартфонных
фотографий с ручными масками, статистикой по небу и заполнением пороговой маски
по небу. Отдельный baseline закрепляет **12 конкретных успешных ID** из
[эксперимента](sky-fill-experiment.md), включая все восемь успехов обычного режима.
Это защита поведения решателя, **не подтверждение астрометрической истины**.

## Запуск

```bash
cd prototype
make eval-smartphone-sky-fill-gate
```

Команда собирает release CLI с `--locked` и создаёт новый каталог
`artifacts/eval/smartphone-sky-fill/run-*`. В нём сохраняются `summary.json`,
`per-frame/`, `solve-reports/`, журнал и `provenance.json` с командой, хешами
бинарника, baseline и масок, версией инструментов и параметрами окружения.
Диагностика детектора до top-K для этого gate не нужна и не включается.

Повторная проверка сохранённого прогона, из `prototype/`:

```bash
python3 eval/sky_fill_gate.py --run-dir artifacts/eval/smartphone-sky-fill/run-EXAMPLE
```

Нужен Python 3 без сторонних пакетов. Новые результаты запускаются в свежих
каталогах; `--run-dir` намеренно проверяет существующие артефакты, не пересчитывая их.
Для нестандартных путей доступны `--manifest`, `--baseline`, `--masks`, `--binary`,
`--out-dir`. Относительные пути в сохранённом summary интерпретируются от `prototype/`.

## Что защищается

- Состав всех 17 кадров, SHA-256 файлов и размеры после EXIF.
- SHA-256 HYG и настройки blind/EXIF/FOV.
- SHA-256 файла ручных масок и состав шести размеченных кадров.
- Точное совпадение аннотации каждого отчёта с закреплённой маской.
- Оба экспериментальных флага в summary; в отчёте кадра они включены только там,
  где действительно есть маска. На остальных 11 кадрах маска отсутствует и флаги выключены.
- Наличие отчётов всех кадров, согласованность ID и статусов, конечность чисел,
  наличие камеры и числовых показателей успешного решения.
- Каждый обязательный успешный ID отдельно. Потеря одного не компенсируется
  новым успехом другого кадра при том же общем результате 12/17.

Успехи на оставшихся пяти кадрах разрешены. Проверка не требует побитового
совпадения камер, времени или детекций и не фиксирует неудачи навсегда.
Она также не вводит новые пороги RMS/log-odds: статус `solved` остаётся решением
движка по его критериям. Проверки внешних соответствий и точности краёв описаны
[отдельно](sky-edge-review.md).

## Разделение с обычным режимом и CI

| Режим | Команда | Baseline | Обязательных успехов |
|---|---|---|---:|
| Обычный | `make eval-smartphone-gate` | `eval/baseline-smartphone.json` | 8 |
| Экспериментальный | `make eval-smartphone-sky-fill-gate` | `eval/baseline-smartphone-sky-fill.json` | 12 |

Обычный gate отвергает экспериментальные baseline и отчёты. Экспериментальный
требует собственного baseline, закреплённых масок и обоих флагов; обычный прогон
или прежний режим только со статистикой не могут его удовлетворить.

В `.github/workflows/eval-gate.yml` добавлена отдельная задача
`smartphone-sky-fill`; её отчёты загружаются как `smartphone-sky-fill-eval`,
включая неудачные запуски. Обычная задача `smartphone` сохраняет свой baseline.
Удалённый запуск CI в этой сессии не выполнялся.

Обновлять экспериментальный baseline следует вместе с новым воспроизводимым
разбором результата и масок. Изменение разметки даже при сохранении числа успехов
меняет условия эксперимента и требует явного обновления её хеша.

в этом изменении не менялся.
