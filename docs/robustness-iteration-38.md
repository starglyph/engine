# Итерация 38: где tetra3 отвергает гипотезы

Для `wm_r_134291495` разделены этапы всех прежних неуспешных поисков:
**26 TooFew, 46 отказов до внутренней проверки, 120 отказов по вероятности
случайного совпадения**. После ручного восстановления пяти опор из
[итерации 37](robustness-iteration-37.md) до внутренней проверки доходят
**190 из 192** попыток, но ни одна её не проходит. Лучшая гипотеза варианта
превышает допустимую вероятность случайного совпадения в **920.8 раза**.

Это локализация этапа отказа, не доказательство дефекта вероятностной
проверки или правильности отвергнутых гипотез. Пороги, source selection,
production и holdout не менялись. Улучшение распознавания не заявляется.

## Входы и наблюдательный эксперимент

Использованы побайтово сохранённые измерения восьми списков итерации 37:
четыре scale/tier control и четыре списка ручного восстановления.
Добавлен прежний положительный development-контроль `wm_r_112929230`
из итерации 36. Новая диагностика не использует пиксели или новые источники.

Для каждого списка сохранены прежние восемь диапазонов FOV, префиксы
`8,10,12,16,20,30`, четыре базы, match radius 0.01, threshold 1e−3
и timeout 2500 ms. Всего **432 вызова**, wall limit 180 s.

Существующий `tetra3_internal.py` создаёт изолированную копию проверенного
по SHA-256 tetra3 0.8.0. Новый модуль
[`tetra3_funnel.rs`](../prototype/eval/tetra3_funnel.rs) добавляет счётчики:

1. Перебранные image-четвёрки после cluster-buster.
2. Встреченные записи с совпавшим 16-bit hash ключа.
3. Записи, прошедшие проверку согласованности FOV.
4. Прошедшие полную проверку отношений расстояний.
5. Успешное вычисление поворота через SVD.
6. Внутренние проверки и гистограмма числа найденных соответствий.
7. Пройденная вероятность случайного совпадения.
8. Успешная финализация WCS внутри tetra3.

Счётчики локальны для одного FOV. Событие записывается при выходе из области
видимости, в том числе при TooFew, успешном возврате и таймауте. На каждом
FOV сохраняется ближайшая к порогу гипотеза: вероятность, порог, четыре
индекса изображения и каталога, пары внутренней проверки, parity и
уточнённый FOV. Полные trace-события локальны; публичная сводка содержит
счётчики и лучшую гипотезу каждой попытки, без округления.

Ни одно условие принятия, ветвление поиска или вычисление геометрии
не изменено. Старые hooks конкретной четвёрки из итерации 4 сохранены,
но не используются для интерпретации нового кадра. Hash-кандидаты —
**посещения записей**, включая коллизии и повторения между ключами/FOV,
а не число уникальных звёзд, полей или правильных соответствий.

До реального запуска закреплены исходники, сгенерированный стенд, списки,
базы, параметры и критерии; бинарник закреплён после сборки и тестов.
Критерии: точное воспроизведение 384 исходов цели; воспроизведение
успешных попыток и идентичностей положительного контроля; полный баланс
счётчиков и однозначная связь `attempt → thinning → funnel`.
Возможная чувствительность таймаута контроля к инструментированию
предусмотрена протоколом, но исходы фактически совпали во всех 432 вызовах.

## Результат по этапам

Число полных попыток, не число FOV:

| Последний достигнутый этап | Исходные списки | Ручное восстановление |
|---|---:|---:|
| TooFew после прореживания | 26 | 0 |
| NoMatch, ни одна четвёрка не прошла проверку отношений расстояний | 46 | 2 |
| NoMatch, есть внутренние проверки, ни одна не прошла вероятность | 120 | 190 |
| Пройдена вероятность / получен tetra3-кандидат | 0 | 0 |
| Таймаут | 0 | 0 |

В 46+2 попытках без внутренней проверки имеются hash- и FOV-кандидаты,
но нет ни одного `ratios_pass`. Поэтому их нельзя описывать как совершенно
пустой поиск в базе. Ни одного отказа SVD после успешных отношений
расстояний в исследованных списках не обнаружено.

Суммарные события по четырём спискам каждого режима:

| Этап | Исходные списки | Ручное восстановление |
|---|---:|---:|
| Перебранные image-четвёрки | 237508 | 357102 |
| Hash-кандидаты | 14345998 | 30390490 |
| Прошли FOV | 7682569 | 16708454 |
| Прошли отношения расстояний | 85444 | 180339 |
| Прошли SVD / вызвана внутренняя проверка | 85444 | 180339 |
| Прошли вероятность | 0 | 0 |
| Вызвана финализация WCS | 0 | 0 |

Для каждого из **12480 FOV цели** проверено, что перебрано ровно
`C(retained,4)` четвёрок. Раннего завершения или таймаута здесь нет.
Таким образом, отрицательный результат не объясняется незавершённым
перебором в выделенном бюджете. Эта проверка относится только к текущим
спискам и диапазонам поиска, не ко всем возможным звёздам и моделям.

## Насколько близки лучшие гипотезы

Внутренний порог tetra3 равен `1e−3 / num_patterns` соответствующей базы.
Ниже отношение `prob_mismatch / внутренний_порог`; пройти можно при
значении **меньше 1**. Это не RMS, не вероятность правильности решения
и не независимая оценка идентичности звёзд.

| Список | Внутренних проверок | Максимум соответствий | Минимум отношения к порогу |
|---|---:|---:|---:|
| 1600 default control | 44054 | 6 | 25885.65 |
| 1600 default manual | 70752 | 6 | 16934.76 |
| 1600 deep control | 33882 | 6 | 8826.76 |
| 1600 deep manual | 70341 | 7 | **920.80** |
| 6016 default control | 3167 | 5 | 731487.76 |
| 6016 default manual | 23234 | 6 | 76432.59 |
| 6016 deep control | 4341 | 6 | 231719.34 |
| 6016 deep manual | 16012 | 5 | 431946.36 |

Лучший manual-пример: reduced deep, bootstrap, k=30, диапазон с центром
15°, проверяемый FOV 15.60°, уточнённый 15.1763°. Семь внутренних пар дают
`prob_mismatch=9.77825e−7` при пороге `1.06193e−9`. Наличие семи пар
само по себе не делает гипотезу правильной; каталоговые идентичности
и геометрия этой гипотезы не проверены независимо. Ослабление проверки
ради неё не обосновано.

У целевого кадра нет даже внутренней финализации WCS tetra3; до проверки
Starglyph и его LM дело не доходит. Итоговые inliers и независимая
геометрия здесь **не определены**.

## Положительный контроль и бюджет

`wm_r_112929230`: как прежде, 45 NoMatch, два кандидата и один Timeout.
Обе успешные попытки и весь JSON результатов, включая идентичности,
точно совпали с итерацией 36: bootstrap 60°/k=30 и dense 48–88°/k=30.

Счётчики контроля: 108746 внутренних проверок, две прошедшие вероятность,
две успешные финализации. Обе прошедшие гипотезы имеют по 10 соответствий
**перед** WCS-refinement tetra3; финальные решения имеют 7 и 11,
как в прежнем replay. Эти разные этапы нельзя смешивать в одном счётчике
inliers. Минимальное отношение вероятности к порогу — 0.00823.

Сумма matcher-времени: исходные списки цели **5.774 s**, ручные **8.324 s**,
положительный контроль **6.739 s**. Весь процесс — **23.136 s**.
Один контрольный timeout остаётся в dense 16–30°/k=30 после первого
полученного кандидата. Стенд продолжает диагностический перебор;
это не таймаут полного production pipeline.

Счётчики и JSON добавляют накладные расходы. Эти времена не сравниваются
с предыдущими итерациями как benchmark производительности, а фиксируют
фактический расход ограниченного диагностического запуска.

## Проверки и ограничения

- **258 Python-тестов**: привязка FOV/попыток, баланс стадий и гистограмм,
  split guards, защита anchors и прежние regression-проверки eval.
- **2 Rust-теста** нового модуля: подсчёт всех проверок и минимума,
  безопасный учёт нечисловых диагностических вероятностей. В реальном
  запуске таких вероятностей нет.
- Изолированная release-сборка; точное воспроизведение всех 432 результатов.
- Строгий Clippy обнаружил прежний лишний `fov as f64` в переиспользованном
  `tetra3_internal.rs`. Повтор с `-D warnings -A clippy::unnecessary_cast`
  прошёл. Это единственное исключение; новый модуль не содержит casts.
  Обе проверки сохранены, замороженный caller не исправлялся задним числом.
- Production Rust, manifest, baseline, split/track и WCS-review не изменены;
  защищённые файлы проверены по хешам. Holdout и отрицательные примеры
  не запускались: алгоритмического изменения нет.

WCS целевого кадра остаётся **unresolved**, как установлено в итерации 36.
Счётчики не превращают внутренние соответствия в ground truth. Они
локализуют последний барьер, но не показывают, встречался ли вообще
правильный каталоговый паттерн. Возможны неверные звёзды, неподходящий
масштаб/проекция или потери во внутреннем наборе проверки — ни одна из
этих причин ещё не подтверждена для данного кадра.

## Следующий шаг

Независимо идентифицировать небольшую группу видимых звёзд и проверить
масштаб/проекцию поля. Затем проследить **именно её** каталоговую четвёрку
через уже имеющийся target-trace и состав внутреннего проверочного набора.
Это позволит отличить правильную, но отвергнутую привязку от множества
случайных геометрических совпадений. До такой проверки ни расширение базы,
ни ослабление вероятности, ни новая эвристика отбора не обоснованы.

python3 eval/robustness_matcher_funnel.py build --out-dir "$ITERATION_OUT"

python3 eval/robustness_matcher_funnel.py summarize --out-dir "$ITERATION_OUT"
python3 -m unittest discover -s eval -p 'test_*.py'

баз предполагают прежний checkout. Перенос путей требует нового протокола.

изолированные исходники, raw JSON, все FOV trace-события и логи проверок.
Protocol/input публикуются побайтово, results — компактно без округления.
