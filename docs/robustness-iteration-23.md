# Итерация устойчивости 23: медианная оценка roll на синтетике

2026-10-05, продолжение [итерации 22](robustness-iteration-22.md), база `93a3299`.

**Простая замена кругового среднего медианой отклонена на предварительной
синтетической проверке.** При известных ложных парах ошибка существенно
снижается, но без ложных пар групповой RMS ухудшается в 6 из 8 групп,
максимум на 63%. Это нарушает заранее зафиксированный критерий сохранения
точности. Вариант не перенесён в production и не запускался на development.
Holdout не использовался.

## Гипотеза и единственный вариант

Итерация 22 показала высокое влияние одной сомнительной пары на круговое среднее
roll сохранённого smartphone-кандидата. Проверяется общее правило, не знающее
ID источника: заменить среднее **медианой индивидуальных углов пар**.

Углы разворачиваются относительно их кругового среднего в интервал ±π,
сортируются; при чётном числе берётся среднее двух центральных значений.
Результат возвращается в интервал ±π. Это локальная оценка для сгруппированных
углов, а не глобальная оптимизация круговой L1-ошибки для произвольного набора
на окружности. Порогов отсечения, весов, выбора по числу проверочных совпадений
и настройки на реальном снимке нет. Все пары остаются входами оценки.

Контроль вызывает настоящий production `pose_from_solution`. Функция кандидата
автоматически извлечена из того же исходника; заменяется только агрегирование
roll. Остальная геометрия и обработка пар идентичны. Оба варианта получают
одни и те же данные, каждый вызывается один раз; порядок чередуется.
Модули подключены только к изолированной копии workspace через `#[cfg(test)]`.

## Независимые известные координаты и матрица

Повторно использованы TAN-фикстуры итерации 17, построенные через геометрический
API tetra3. Они отделены от тестируемой оценки roll. Пиксельное представление
опор согласовано с известным геометрическим центром сдвигом +0.5 px;
новая поправка центра не исследуется и в production не включается.

| Параметр | Зафиксированные значения |
|---|---|
| Размеры | 1600×1200, 1989×1498 |
| Горизонтальный FOV | 22°, 85° |
| RA, Dec, θ в TAN-фикстуре | (30°, 20°, 15°), (210°, −35°, 179.8°) |
| Охват опор | весь кадр; верхняя часть |
| Число пар | 13, 20 |
| Шум центроидов по каждой координате | Gaussian σ = 0.25 или 1 px |
| Реализации шума | 8 seed для каждой конфигурации |
| Ложные пары | 0; одна; floor(n/4), то есть 3 или 5 |
| Ошибка ложной идентичности | поворот каталожной точки вокруг оптической оси на ±1° или ±5° |
| Контрольные точки | 63 точки по полю, не используемые в оценке |

θ фикстуры не приравнивается к roll Starglyph: качество оценивается по проекциям
известных точек, без ручной поправки соглашения об углах. Граничный переход
±180° дополнительно проверен отдельным unit test самого оценивателя.

Для каждого seed создаётся один и тот же шум детекций во всех сценариях.
Ложное соответствие меняет только каталожный вектор выбранной пары;
пиксельная детекция сохраняется. Выбор индексов детерминирован, знак смещения
чередуется по seed. Несколько ложных пар в одном случае имеют одинаковый знак.
Точный генератор и каждый список изменённых индексов сохранены.

Всего **2 592 случая**: 32 без шума и ложных пар, 512 с шумом без ложных пар,
2 048 с ложными парами. Для каждого сохранены обе оценки, RMS и максимальная
ошибка на 63 контрольных точках, угол и время. Поиск tetra3, LM, проверка
принятия решения и обработка реальных фотографий в эксперимент не входят.

## Критерии, зафиксированные до измерения

Переход к development разрешён только при одновременном выполнении:

1. Максимальная ошибка обоих вариантов без шума ≤ 0.01 px.
2. В каждой чистой группе (σ, охват, число пар) отношение групповых RMS
   median/control ≤ 1.10. Групповой RMS — корень среднего квадрата RMS случаев.
3. Ни в одном чистом случае увеличение RMS не превышает 0.5 px.
4. В каждой группе с ложными парами (число как доля, угол ошибки) отношение
   медиан RMS случаев median/control ≤ 0.75, то есть снижение не менее 25%.

Критерии не менялись после просмотра результатов. Они ограничивают допуск
варианта к более дорогой проверке, а не сертифицируют solve rate.

## Результаты на чистых данных

Без шума оба варианта имеют максимальную ошибку **0.00006772 px**: первый
критерий выполнен. При шуме результат зависит от геометрии и числа опор.

| Охват | Пар | σ, px | RMS control, px | RMS median, px | Отношение |
|---|---:|---:|---:|---:|---:|
| полный | 13 | 0.25 | 0.06788 | 0.04198 | 0.619 |
| полный | 20 | 0.25 | 0.05350 | 0.08714 | **1.629** |
| верхняя часть | 13 | 0.25 | 0.05020 | 0.06334 | **1.262** |
| верхняя часть | 20 | 0.25 | 0.06553 | 0.08082 | **1.233** |
| полный | 13 | 1.00 | 0.27187 | 0.16816 | 0.619 |
| полный | 20 | 1.00 | 0.21386 | 0.34865 | **1.630** |
| верхняя часть | 13 | 1.00 | 0.20079 | 0.25330 | **1.262** |
| верхняя часть | 20 | 1.00 | 0.26165 | 0.32336 | **1.236** |

В каждой группе 64 случая. **Шесть групп нарушают предел 1.10.** При 13 опорах
с полным охватом медиана улучшает результат; утверждать, что она всегда хуже
на чистых данных, нельзя.

Наибольшее увеличение RMS одного чистого случая — **0.48822 px**,
`case-0805`: 1600×1200, FOV 85°, полный охват, 20 пар, σ = 1 px, seed 7.
RMS меняется **0.32994 → 0.81816 px**, максимальная ошибка контрольной точки —
0.50566 → 1.25389 px. Третий критерий формально выполнен, но это не отменяет
провала группового критерия.

## Проверки, время и воспроизводимость

Финальный процесс с экспортом и четырьмя диагностическими unit tests завершён
за **0.215 s**, лимит 120 s; все случаи измерены, ошибок и таймаутов нет.
Медиана времени вызова адаптера: control **2.395 μs**, median **3.907 μs**.
Замеры включают только оценку позы, не оценку контрольных точек, и не служат
прогнозом скорости полного pipeline.

Прошли **188 Python-тестов**, **101 Rust unit test** (7 ignored), отдельный
экспорт, rustfmt новых и сгенерированного модулей, Clippy core
`--all-targets --no-deps -D warnings`. Среди Rust-проверок — существующие
refinement regression tests и `blind_solve_g128_real_frame`. Новые проверки
охватывают границу ±180°, перестановку пар, поворот всех углов, чётный размер,
нечисловые входы, неизменность детекций при порче идентичностей, полноту матрицы
и блокирование перехода при регрессии чистых групп.

После первого измерения исправлены только замечание Clippy о проверке чётности
seed и лишняя пустая строка сгенерированного Rust-файла. Также повторно
использован существующий каталоговый кэш для unit regression test. Исходный
протокол и результат сохранены локально в `pre-lint/`; окончательный протокол
зафиксирован перед повтором. **Все геометрические числа и индексы 2 592 случаев
совпали точно**; параметры, данные и критерии не подбирались. Первичная команда
`cargo fmt` не нашла targets из внешнего workspace; форматирование проверено
напрямую для затронутых модулей.

## Ограничения и следующий шаг

Это проверка геометрической оценки при известном истинном поле. FOV и центр
направления заданы точно, дисторсии нет; ошибки идентичностей сконструированы,
а не получены реальным поиском tetra3. Каталожное соседство, неоднородный фон,
ошибки детектора и неоднозначные WCS этим не моделируются.

Шумы повторно используются между геометрическими конфигурациями: число случаев
не означает столько же независимых случайных наблюдений. Восемь seed дают
ограниченную детерминированную проверку; доверительные интервалы и общая
частота регрессий не оцениваются. Малые абсолютные изменения некоторых групп
сами по себе не доказывают ухудшения solve rate. Решение остановить вариант
следует из консервативного предварительного критерия.

**Автоматическое улучшение не подтверждено.** Исходные данные, опубликованный
baseline и production-код сохранены. Development, stress/negative и holdout
не запускались, ground truth и WCS-review не менялись.

Следующий обоснованный вариант — мягкая робастная оценка, сохраняющая влияние
близких согласованных пар и ограничивающая далёкие угловые остатки. Её правило
масштаба и параметры следует зафиксировать отдельно, прежде чем измерять;
при этом учитывать, что одинаковая пиксельная ошибка даёт разные угловые ошибки
на разном расстоянии от центра. Нельзя выбирать правило по детекции 5 или
числу прошедших проверку совпадений. Настоящую матрицу после этой итерации
следует считать development-синтетикой; для нового варианта нужны дополнительные
заранее зафиксированные реализации шума для проверки переноса.
