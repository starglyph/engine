# Независимые астрометрические эталоны

Результат распознавателя — измерение, а не эталон для проверки самого себя. Для
реальных кадров используем локальный Astrometry.net с отдельными каталоговыми
индексами. Для синтетики истину задаёт камера симулятора.

## Установка и запуск

В Ubuntu 22.04 доступен Astrometry.net 0.89. Для широких полей нужны пакеты
`astrometry.net`, `astrometry-data-tycho2-10-19`, `python3-astropy`, `python3-numpy`,
`python3-pil`. Пример конфигурации backend:

```text
cpulimit 30
add_path /usr/share/astrometry
autoindex
```

Без root пакеты с зависимостями можно скачать через `apt-get download` и распаковать
`dpkg-deb -x` в локальный каталог. Тогда нужны `PATH`, `LD_LIBRARY_PATH`, `PYTHONPATH`
для распакованного дерева, совместимый системный Python и абсолютный `add_path`.
Для пакетного Astrometry.net 0.89 нужен NumPy до 1.24 (например, `numpy==1.23.5`): его Python-утилиты
используют старые псевдонимы `np.bool` и `np.string_`. При распаковке Debian/Ubuntu
добавляйте в `LD_LIBRARY_PATH` оба каталога `usr/lib` и `usr/lib/x86_64-linux-gnu`.
Пакеты и индексы не добавляются в Git. Скрипт обрабатывает фотографии локально;
опубликованная с разрешения автора [серия смартфона](../data/input/smartphone/README.md)
имеет отдельный манифест и лицензию CC BY 4.0.

Из `prototype/`:

```bash
python3 eval/solve_local_wcs.py ../data/input/smartphone \
  --out-dir artifacts/smartphone-wcs \
  --config /path/to/astrometry.cfg \
  --index-dir /usr/share/astrometry --cpu-limit 30

target/release/starglyph eval --manifest /path/to/manifest.json \
  --catalog ../data/catalogs/hyg_v42.csv.gz \
  --out-dir artifacts/smartphone-eval

python3 eval/compare_local_wcs.py \
  --references artifacts/smartphone-wcs/summary.json \
  --reports-dir artifacts/smartphone-eval/solve-reports \
  --output artifacts/smartphone-eval/wcs-comparison.json
```

ID в eval-манифесте должен совпадать с именем исходного файла без расширения.
WCS-скрипт пробует уменьшение в 4 и 2 раза, сортировку по фону-вычтенному потоку,
отключённое пространственное выравнивание списка источников и погрешность проверки
4 px. Порог принятия Astrometry.net остаётся штатным. Подсказок из Starglyph скрипт
не использует, изображения по сети не отправляет. При wall-clock timeout завершается
вся группа процессов попытки. CPU ограничивается отдельно.

## Артефакты и приёмка

- `input.fits`: полный кадр после EXIF, с сохранённым диапазоном серого сенсорных TIFF.
- `downsample-*/field.wcs`, `.corr`, `.axy`, `solve.log`: полный WCS, внешние
  соответствия, обнаруженные источники и журнал попытки.
- `reference.json`: SHA-256 исходника, FITS, WCS и соответствий; размеры, ориентация,
  статус, сетка небесных координат и показатели соответствий.
- `summary.json`: версия Astrometry.net, конфигурация, SHA-256 индексов и точные
  команды. При прерывании сверять `completed` с `input_count`.

Успешная привязка получает `status: solved_candidate`, `review_status: pending`.
Отказ остаётся `unresolved`. Перед повторной попыткой старые маркеры успеха удаляются.

Перед ручным `review_status: accepted`:

1. Проверить SHA-256 и ориентацию: сравниваются те же пиксели.
2. Наложить звёзды `.corr` на FITS; проверить идентификации ярких звёзд, остатки,
   число соответствий с `match_weight ≥ 0.95` и охват по обеим осям.
3. Проверить центр и края отдельно. Малый участок опорных звёзд не подтверждает SIP
   на всём поле. Остатки обучающих соответствий не являются внешней точностью.
4. Записать проверяющего, версию, пригодную область и ограничения. Неоднозначные
   решения остаются кандидатами либо отклоняются.

Для точной астрометрии дополнительно нужны независимые контрольные звёзды, учёт
эпохи, собственного движения и атмосферных эффектов.

## Координаты и метрики

JSON: нулевые координаты, `x` вправо, `y` вниз после EXIF Orientation. В FITS строка 0
также соответствует верху исходного изображения; Astropy вызывается с `origin=0`.
Таблица `.corr` начинается с 1: при сравнении с движком вычитается 1 из обеих осей.
Переворот строк и эмпирические поправки roll для JPEG здесь не применяются.

`compare_local_wcs.py` проверяет хеши и размеры и вычисляет в исходных пикселях:

- `full_field_wcs_difference`: расхождение проекций на сетке 9 × 9 по всему кадру,
  включая края вне области опорных звёзд;
- `external_star_error`: ошибку камеры Starglyph на звёздах внешнего каталога
  относительно центроидов `.corr` с весом ≥ 0.95;
- `external_wcs_fit`: собственные остатки внешней привязки на тех же звёздах.

Для каждой метрики сохраняются RMS, median, p95, max. Сравнение не подгоняет камеру
под WCS и не превращает `pending` в принятый эталон. Старый eval по кратким nova
JSON-sidecar сохраняется отдельно: `pixscale × width` и конвенции roll исторического
набора не задают точную геометрию новых широкоугольных кадров.

## Источники

- [Astrometry.net README](https://astrometry.net/doc/readme.html): индексы, параметры
  solve-field и выходные файлы.
- [Astropy WCS API](https://docs.astropy.org/en/stable/wcs/wcsapi.html): преобразования
  пикселей и небесных координат.
- Пакет `astrometry-data-tycho2-10-19`: файл
  `/usr/share/doc/astrometry-data-tycho2-10-19/copyright` указывает BSD-2-Clause и
  согласование с автором Tycho-2. Другие индексы требуют отдельной проверки провенанса.

## Визуально проверенные внешние источники

`eval/verify_masked_wcs.py --source-review ...` позволяет повторить слепой поиск
по замороженным меткам собственного извлечения Astrometry.net. Хеш `.axy` и номера
строк обязательны; исходные центроиды сохраняются. `eval/review_external_stars.py`
сравнивает сохранённые каталоговые соответствия с камерой без её подгонки.
[Протокол, результаты и ограничения](sky-fill-review.md).

`--roi X0 Y0 X1 Y1` ограничивает внешнее поле одним прямоугольником исходного
ориентированного изображения; требуется один `--ids`. Возвращаемые WCS и `.corr`
переводятся обратно в координаты полного кадра. Это не подтверждает экстраполяцию
вне прямоугольника. `--solver-config` вместе с `--solver-index-dir` явно переключает
каталог проверки, сохраняя отдельно происхождение исходного извлечения и проверки.
`eval/build_hyg_review_indices.py` строит локальные индексы из уже имеющегося HYG:
они проверяют другой алгоритм, но используют общий с движком каталог.
[Результаты, ограничения и команды](sky-edge-review.md).
