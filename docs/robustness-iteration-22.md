# Итерация устойчивости 22: влияние отдельных пар на roll

2026-10-05, продолжение [итерации 21](robustness-iteration-21.md), база `93a3299`.

**Подтверждена чувствительность roll к одной сомнительной паре.** Если исключить
пару детекции 5 только из кругового среднего угла, сохранённый centered-кандидат
получает 6 совпадений вместо 3 при неизменной проверке. Это объясняет, как одна
опора может переключить результат проверки данного кандидата. Ложность самой
пары и автоматическое улучшение распознавания этим не доказаны. Production-код
и отвергнутый в итерации 18 вариант центра остаются без изменений.

## Гипотеза и фиксированные входы

В предыдущих итерациях обнаружены большой угловой остаток пары детекции 5
с HYG 99366 и неподтверждённая повторяемость источника на соседнем снимке.
Гипотеза: равновесное круговое среднее всех пар чувствительно к этой опоре
настолько, что меняет независимое сопоставление проекций с детекциями.

Использованы два **первых сохранённых кандидата** legacy smartphone-кадра
`20260831_214709` из итерации 19: control и centered. Это не новый пример из
коллекции robustness-2026-10. Holdout, development, stress и negative коллекции
не запускались; их измерения и принадлежность к split не изменялись.

Для каждого кандидата выполнены baseline и 13 поочерёдных исключений пары:
всего **28 случаев**, без выбора лучшего поднабора. Каждая пара исключается
только из аргументов `pose_from_solution`, задающих круговое среднее roll.
RA, Dec, focal, k1, размеры кадра и остальные параметры кандидата фиксированы.
В `match_predictions` всегда передаются **все 50 исходных детекций** и полный
каталог проверки: **12 495 звёзд**, magnitude ≤ 6.8, в исходном порядке.
Исключённая из roll детекция остаётся доступна проверке.

Вызываются настоящие неизменённые Rust-функции production-кода в отдельной
копии workspace. Новый модуль подключён только через `#[cfg(test)]`.
Порог расстояния — **3 px**; hard-путь требует исходных tetra3 matches ≥ 6,
prob < 1e-5 и ≥ 6 проверочных совпадений. Soft-путь сохраняет log-odds ≥ 18
и ≥ 6 совпадений. LM не выполняется. Новый tetra3-поиск не запускается;
его исходные 13 matches и prob ≈ 5.492226e-6 не пересчитываются.
Поэтому значения gate в JSON обозначены как **контрфактические при сохранённом
свидетельстве поиска**, а не как новый статус `solved`.

Протокол и хеши входов зафиксированы до успешного измерения. Воспроизведение
включает выбор эпохи командой `eval` и fallback распознавателя. Формат имени
этого снимка не поддержан парсером времени; фактически используется EXIF,
epoch **2026.6650451872138**. Векторы всех сохранённых пар совпали с заново
построенным каталогом до 1e-14; камера и численные показатели baseline —
до 1e-10, проверочные соответствия совпали точно.

## Результаты

Все расстояния ниже — в рабочем изображении **1600×901**. Здесь «совпадения»
означают результат проверки до LM, а не итоговые inliers полного solve.

| 1 | −0.013684 | 7 | 3 |

| 3 | −0.009955 | 7 | 3 |
| **5** | **−0.136464** | **6** | **6** |

Детекция 5 имеет наибольшее абсолютное влияние на roll в обоих вариантах.
Её исключение меняет control roll с −1.957318° до −2.089044°, centered —
с −1.976007° до −2.112471°. Максимальное перемещение проекции среди исходных
13 пар составляет соответственно **1.833 и 1.897 px**.

У centered после этого проходят детекции **37, 16, 3, 13, 0, 2**;
в baseline проходили только 37, 3, 13. Детекция 5 не проходит ни до, ни после
исключения из roll: ошибка её исходной пары растёт с 11.967 до 12.656 px.
Таким образом, эффект возникает за счёт поворота остальных проекций,
а не удаления этой детекции из числа проверяемых источников.

| Показатель | Control baseline | Control без пары 5 в roll | Centered baseline | Centered без пары 5 в roll |
|---|---:|---:|---:|---:|
| Совпадения при 3 px | 7 | 6 | 3 | 6 |
| RMS принятых совпадений, px | 2.510 | 2.287 | 2.446 | 2.771 |
| RMS всех исходных 13 пар, px | 6.841 | 6.751 | 6.824 | 6.726 |
| Log-odds | −34.181 | −42.842 | −68.824 | −42.842 |
| Условный hard gate | да | да | нет | да |
| Soft gate | нет | нет | нет | нет |

Исключение пары 5 — единственный из 13 случаев, переводящий centered через
hard gate. При этом control теряет одно совпадение. Исключение пары детекции
14 переводит control ниже hard gate: 7 → 5. В остальных случаях control
сохраняет 6–7 совпадений; ни один случай обоих вариантов не проходит soft gate.

RMS принятых совпадений нельзя сравнивать как независимую оценку геометрии:
состав меняется. RMS исходных 13 пар также не является ground truth: часть
идентичностей остаётся спорной. Улучшения геометрии по независимым опорам
в этой итерации не измерено; внешний WCS остаётся pending.

## Время, проверки и ограничения

Успешный диагностический процесс занял **0.622 s**, лимит 120 s.
Один вызов адаптера и проверки занимал 0.112–1.347 ms; медианы control/centered
составили 0.136/0.116 ms. Это описательные замеры малого replay, без поиска
tetra3 и загрузки каталога внутри интервала; вывод о скорости pipeline не делается.
Все 28 случаев завершены, ошибок и таймаутов успешного измерения нет.

Прошли **183 Python-теста**, **97 Rust unit tests** (7 ignored, включая явно
запускаемый экспорт), отдельный экспорт replay, rustfmt и Clippy core
`--all-targets --no-deps -D warnings`. Rust-проверки включают прежние тесты
refinement и `blind_solve_g128_real_frame`. Полные collection/smartphone gates
не повторялись: production-поведение не изменено, новый модуль существует
только в изолированном диагностическом workspace.

Предварительная сборка выявила неправильный тип поля rank в тестовом модуле;
следующий предварительный запуск остановился на неверном предположении о
разборе имени файла. Оба исправлены до итогового протокола, их логи сохранены.
Дополнительный Clippy без `--no-deps` остановился на существующем
`simulator-core::build_frame_metadata` (`too_many_arguments`); штатный для этих
экспериментов Clippy core без зависимостей прошёл. Посторонний код не изменялся.

Чувствительность одной сохранённой позы не доказывает общую причину всех
development-отказов. Здесь нет нового автоматического алгоритма, измерения
solve rate или оценки ложных принятий. Даже успех на единственном negative
holdout не позволил бы оценить их частоту; этот кадр не использовался.

## Следующий шаг

Проверить общую устойчивую оценку roll на синтетических наборах с известными
верными и ложными парами, включая случаи без выбросов и ограниченный охват поля.
Правило должно работать без знания ID детекции 5. Только после такой проверки
зафиксировать один вариант и сравнить его с production на development и прежних
regression gates при прежней независимой проверке. Простое удаление этой пары,
подбор roll по максимальному числу hits или включение centered по данному replay
не обоснованы. Holdout остаётся закрытым для подбора.
