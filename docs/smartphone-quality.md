# Проверка качества смартфонного набора — 2026-10-02

## Условия и воспроизводимость

Исходная версия движка: `378a8ec` (PR #16). В этом цикле изменены выбор каталога
CLI и измерительная инфраструктура; алгоритм распознавания и его пороги сохранены.
Набор: все 17 опубликованных кадров из `data/input/smartphone/manifest.json`.
Каталог HYG v4.2; EXIF включён; нет глобальной подсказки FOV и межкадровых подсказок.

Окружение: Linux x86_64, AMD EPYC-Rome, 4 доступных CPU, Rust 1.98.1,
Python 3.10.12; release-сборка CLI 0.1.0. Первый прогон с генерацией баз
использовался для прогрева. Замеры повторных прогонов относятся к готовому кэшу;
это характеристика этой машины, не обещание задержки на других устройствах.

Из `prototype/`:

```bash
make eval-smartphone-gate
make eval-smartphone-gate
make eval-gate
```

Каждый смартфонный прогон сохраняет `summary.json`, `per-frame/`, `solve-reports/`,
`solve.log` и `provenance.json` в отдельный каталог `artifacts/eval/smartphone/run-*`.
Провенанс включает хеш бинарного файла, коммит, хеш diff, инструменты, команду,
машину и перечень баз до запуска. Хеши входов, каталог и обязательные успешные ID
закреплены в `prototype/eval/baseline-smartphone.json`.

## Зафиксированный результат

Холодный прогон и оба повторных прогона дали **8/17**, причём набор успешных ID
совпал полностью. Параметры камер восьми решений между двумя повторами
совпали точно. Новый смартфонный gate и существующий tetra3 gate прошли.

| Прогон с готовым кэшем | Полное время процесса, s | Медиана total на кадр, s | p95 total, s | Максимум total, s |

| Первый | 146.38 | 5.26 | 27.48 | 43.97 |
| Второй | 140.24 | 5.30 | 26.35 | 48.28 |

загрузку базы, чтение входов и запись артефактов. Первый повтор частично совпал
с отдельной проверкой tetra3, поэтому разницу времени не следует трактовать как
изменение производительности алгоритма. Успешные кадры второго повтора занимали
0.31–1.30 s по `total`, неуспешные — 5.30–48.28 s.

Оба повтора использовали один бинарный файл SHA-256

Проверки кода: 93 Rust-теста прошли (один тест и три doc-теста игнорируются

## Независимая проверка WCS

Воспроизведены все три ранее известных кандидата. Использованы Astrometry.net
0.89, Tycho-2 10–19, Astropy 6.1.7, NumPy 1.23.5, Pillow 12.3.0;
CPU-limit 30 s, уменьшение 4/2 и остальные параметры `solve_local_wcs.py`.
Фото не отправлялись в сеть. Хеши исходников, размеры после EXIF и хеши WCS/`.corr`
проверены; выполнен визуальный просмотр наложенных соответствий.

| Кадр | Соответствия с весом ≥0.95 | RMS движка на внешних звёздах, px | RMS внешней WCS, px | p95 расхождения WCS в центре / у краёв, px |
|---|---:|---:|---:|---:|
| `20260829_220801` | 28 | 6.78 | 4.58 | 6.33 / 33.71 |
| `20260829_221011` | 39 | 3.52 | 5.56 | 5.36 / 76.47 |
| `20260831_214709` | 49 | 11.67 | 7.31 | 9.13 / 63.71 |

Центр — точки сетки 9×9 в пределах 20–80% ширины и высоты; края — остальные
точки этой сетки. Расхождение двух моделей не равно абсолютной ошибке движка.
RMS внешней WCS измерен на её собственных соответствиях, а не на контрольной
выборке. Числа в таблице отфильтрованы по `match_weight ≥ 0.95`; первоначальные
`fit_rms_px` в `reference.json` включают также соответствия меньшего веса.

**Итог проверки всех трёх: `pending`, принятых областей нет.** Проверяющий — Codex,
диагностический обзор 2026-10-02; это не сертификация точной астрометрии.

- `20260829_220801`: в верхнем левом углу нет надёжных опорных соответствий;
  заметно расхождение моделей на краях.
- `20260829_221011`: три из четырёх углов без опорных соответствий; большое
  расхождение у краёв при относительно малых остатках на звёздах в покрытой области.
- `20260831_214709`: нижний правый угол без опорных соответствий, повышенные
  остатки на внешних звёздах и краевые расхождения.

Для подсчёта углов использованы крайние четверти каждой оси. Отсутствие контроля
по углам и независимых контрольных звёзд не позволяет принять всё поле.
Идентификации ярких звёзд не сертифицированы независимым экспертом. Полные TAN/SIP
WCS и `.corr` остаются отдельными локальными артефактами, поле `wcs` исходного
манифеста остаётся `null`.

Локальные результаты: `artifacts/smartphone-wcs-compatible/` содержит
`summary.json`, полные WCS, `.corr`, `comparison.json`, `review.json` и изображения
`correspondences-review.jpg` для каждого кандидата. Эти генерируемые файлы
не входят в Git. Повторение привязки и сравнения описано в [local-wcs.md](local-wcs.md).

## Диагноз отказов

Все девять отказов имеют код `no_confident_match`. Нет оснований заменять этот
диагноз утверждением «на фото мало звёзд»: 43–50 детекций не равны 43–50 звёздам.
Визуальная сверка детекций показывает попадания на здания, деревья и освещённые
конструкции. Причинная роль каждого эффекта требует контролируемого эксперимента.

| Кадр | Детекций в отчёте | Охват по X / Y | total второго повтора, s | Наблюдение и гипотеза |
|---|---:|---:|---:|---|
| `20260829_215839` | 50 | 78% / 97% | 7.44 | Много точек на дереве; гипотеза вытеснения звёзд передним планом. |
| `20260829_215934` | 50 | 97% / 91% | 20.87 | Детекции на освещённой конструкции и зданиях; проверить список звёзд после маски. |
| `20260829_215950` | 50 | 91% / 83% | 12.02 | Передний план занимает значительную часть списка; аналогичный эксперимент. |
| `20260829_220020` | 50 | 86% / 48% | 7.22 | Точки сконцентрированы в нижней части изображения, на переднем плане. |
| `20260829_220101` | 50 | 96% / 34% | 6.11 | Ещё более узкая нижняя полоса детекций; гипотеза той же причины. |
| `20260829_220657` | 43 | 99% / 97% | 13.95 | Облака, передний план; кандидаты matching отвергаются независимой проверкой. |
| `20260829_220706` | 50 | 99% / 95% | 11.56 | Передний план; кандидаты около FOV 71° не проходят независимую проверку. |
| `20260829_220732` | 50 | 94% / 97% | 48.28 | EXIF-приор около 23°, слабые blind-кандидаты около 40°; проверить масштаб/приор отдельно. |
| `20260831_214748` | 50 | 31% / 19% | 5.30 | Почти весь список сосредоточен на дереве и нижнем переднем плане. |

Охват — размах координат сохранённых детекций, делённый на размер кадра; это
не доля неба и не покрытие истинными звёздами. В отдельных попытках журнала есть
`Timeout`, но весь проход завершён: таймаут отдельной попытки не доказывает, что
увеличение бюджета решит кадр. Неподтверждённые кандидаты не приняты за успех.

## Следующие эксперименты

1. **Передний план.** На шести кадрах с явным загрязнением (`215839`, `215934`,
   `215950`, `220020`, `220101`, `214748`) вручную разметить маску неба для
   диагностического A/B-прогона в исходной геометрии. Проверить, освобождается ли
   список детекций для звёзд и появляются ли независимо проверенные решения.
   Это исследование для выбора будущего алгоритма маски, не его внедрение.
2. **Масштаб и EXIF.** На `20260829_220732` сравнить текущий режим с отключением
   EXIF-приора, сохранить все попытки, инлаеры и внешнюю проверку. Не считать
   появление непроверенного кандидата улучшением.
3. **Геометрия краёв.** На трёх WCS-кандидатах получить контрольные звёзды вне
   набора подгонки и проверить TAN/SIP и модель камеры отдельно. До этого не
   выбирать новую модель дисторсии по расхождению двух неподтверждённых проекций.

Для будущих изменений сохраняется запрет потери любого из восьми baseline-успехов.
Распределение по трекам, алгоритм и пороги в этом цикле не изменялись.
